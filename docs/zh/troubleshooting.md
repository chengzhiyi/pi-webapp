# 常见问题

先确认[启动方式](./index)和[版本](./reference)。不要同时重复启动、反复提交任务或删除 Pi 数据来试错。以下检查不要求提供密钥。

| 症状 | 检查 | 安全处理与反馈 |
| --- | --- | --- |
| 浏览器打不开或没有自动打开 | 后台启动器用 `npx pi-webapp status`；是否远程/无图形环境或设置了 `PI_WEBAPP_AUTO_OPEN=0` | 从原终端重新打开实际本机地址；远程访问使用私有转发，不公开令牌。反馈系统、启动方式、脱敏报错 |
| 提示 Pi 太旧 | `pi --version` 是否 ≥ 0.87.1，`node --version` 是否 ≥ 22.19 | 通过可信安装方式更新对应运行时；启动器不会覆盖旧 Pi。反馈实际版本，不只说“最新版” |
| 源码更新后界面还是旧的 / 页面连旧桥接 | 是仅刷新了网页，还是重建并重载了后端？ | 结束任务后按源码流程重建、重启；`pi -e .` 用 `/reload` 再 `/web`。反馈运行方式、源码提交、运行版本 |
| 登录页成功但聊天仍未认证 | 提供方回调是否能到达 Pi 所在机器，模型是否支持当前输入？ | 按页面提示手动输入授权码或重新登录；不要把密钥/授权码贴到聊天或反馈里。反馈提供方名称和脱敏错误 |
| 插件开关不可用 / Git 提示忙碌或锁 | 所有聊天是否空闲？是否存在真实 Git 操作、冲突或其他工作树占用？ | 等待相关操作完成，重新读取状态；不要盲删锁、强切分支或丢弃改动。外部插件用「包与扩展」而非内置开关 |
| 升级后页面不回来 | `status`、运行版本、`launcher.log` 的退出原因 | 按[恢复流程](./updates)检查，确认任务结束后再启动。反馈旧/新版本和脱敏生命周期日志片段 |
| 终端标签消失 / 预览不更新 | 是否刷新网页、停服务，或断线超过 5 分钟？ | 终端不跨重启恢复；检查任务副作用后再执行，不盲目重放输入。文件预览用手动刷新；反馈操作顺序 |
| macOS 拦截桌面测试版 | DMG 校验与安装后 `codesign` 是否通过，构建号是否为新流程？ | 按[桌面指南](./desktop)明确同意测试限制；校验失败停止，不重签、不全局关闭安全保护 |

## 反馈最小信息

到[项目 Issues](https://github.com/chengzhiyi/pi-webapp/issues)提供：系统/架构、Node/Pi/pi-webapp 版本或桌面构建号、启动方式、最小复现步骤、预期/实际结果、脱敏错误或必要截图。源码问题附提交号。

日志默认位于 `~/.pi/agent/pi-web/launcher.log`，Windows 对应 `%USERPROFILE%\.pi\agent\pi-web\launcher.log`，自定义数据根目录见[配置](./reference)。**先审查片段再分享**；排除完整访问 URL、令牌、工作区绝对路径、对话私密内容、附件、`auth.json` 和私钥。不要把整个数据目录打包上传。

# 安装与首次对话

## 1. 检查前置条件

浏览器方式需要 Node.js **22.19 或更新版本**，以及 npm。运行 `node --version` 检查。启动器找不到 Pi 时会通过 npm 安装官方 `@earendil-works/pi-coding-agent`；已有 Pi 必须 **0.87.1 或更新版本**，不会被自动覆盖。可用 `pi --version` 检查。

桌面包自带运行时，无需照此安装全局 Node/Pi，先读[桌面指南](./desktop)。首次下载、Pi 安装及模型请求需要相应网络访问。

## 2. 启动 Web

在希望作为工作区的目录中运行：

```bash
npx pi-webapp
```

本地图形桌面会打开默认浏览器，Pi 留在后台。无图形环境只打印本机地址；不要把它当公网地址。再次运行会重新打开已有服务，不会为每个终端创建一个新服务。

可选全局安装：

```bash
npm install -g pi-webapp
pi-webapp
```

远程环境不要通过开放监听端口或分享令牌来解决访问问题；先采用自己管理的安全本机转发，且不要把转发地址公开。见[安全指南](./security)。

## 3. 配置模型并完成第一轮

1. 在界面中打开「设置 → 模型」（首次配置也会引导到模型页）。
2. 选择你有权使用的提供方和模型，按界面支持的方式添加认证或登录。网页登录会打开提供方授权页；回调到不了运行 Pi 的机器时，按页面提示手动输入授权码。不要把密钥发到聊天里。
3. 返回对话，在侧栏选择工作区；需要其他目录时添加工作区，确认路径无误后新建会话。默认使用启动目录时也要确认当前工作区。
4. 选择可用模型，先发一条不改文件的消息，例如「请说明你可以如何协助我，先不要修改文件」。
5. 看到流式回复结束、没有认证报错即完成首次对话。需要操作文件前，明确范围和允许的行为。

没有回复？按[常见问题](./troubleshooting)检查认证、版本和服务状态，不要反复提交相同任务。

## 4. 状态与停止

```bash
npx pi-webapp status
npx pi-webapp stop
```

全局安装后可用 `pi-webapp status` / `pi-webapp stop`。**停止服务会结束全部聊天后台任务和服务终端**；先处理未完成的任务。关网页不等于停服务。

## 已有 Pi 终端的替代方式

```bash
pi install npm:pi-webapp
pi
```

在 Pi 中输入 `/web`。浏览器与该终端会话同步；地址里的随机令牌只在当前进程期间有效。再次输入 `/web` 可重新打开。结束该 Pi 进程才是结束这一方式的服务，不要套用后台启动器的停止/网页升级流程。

# 运行中追加提示词：DSH 完整交互（ORI-18）

## 当前交互与验收口径

本版按用户最新反馈修正此前仅对齐外观的实现：**运行中直接输入并发送 → 进入待处理队列 → 每项可以编辑、删除或发送为引导**。参考 `deepseek-harness@687f282e86` 的 `ui-conversation/QueueDock` 与 `InputBar`，不引入 DSH 运行时。

| 操作 | 行为 |
| --- | --- |
| 运行中输入文字/附件，点发送或 Enter | 默认排队，清空输入框；尚未成为历史消息 |
| 队列项「编辑」 | 原地编辑正文；Enter 保存、Shift+Enter 换行、Esc 或取消按钮放弃；原附件保留 |
| 队列项「删除」 | 删除该唯一队列项，不改输入框，不影响同文案的其他项 |
| 队列项「发送（引导）」 | 仅在会话运行中可用，将该项交给 Pi 原生 `steer`，在下一个输入边界接收，不强杀当前工具 |
| Ctrl/Cmd+Enter | 保留直接引导的快捷方式，不需要先排队；普通发送流程不要求预选引导/排队 |
| 当前任务正常结束 | 按 FIFO 自动发送下一个待处理项，不创建并发 Agent |
| 暂停/错误/待处理审批 | 不自动启动下一条；暂停保留队列，继续后再处理；已有审批不能被引导绕过 |

空草稿的主圆形按钮为暂停；有草稿时为发送，旁边保留独立暂停。不再在输入框旁放置额外的引导按钮。队列采用贴合输入框的内缩 dock：单条直接展示，多条默认折叠，可点击或键盘展开。附件为紧凑文件标签；320px 窄屏将行操作换到下一行。浅深主题、悬停说明、禁用状态和键盘焦点均使用现有共享组件。

## 队列所有权与 Pi 边界

Pi 0.87.1 公开接口没有按队列项 ID 编辑、删除的能力。此前直接调用原生 follow-up 并展示只读队列，不能满足本需求。本版增加**服务端可编辑待发队列**：

- `EditablePromptQueue` 是 Web 追加消息在移交 Pi 前的唯一所有者，保留正文、附件/图片及请求关联信息；不清空或篡改 Pi 的内部队列，不清空再重建原生队列。
- 每项具有稳定 UUID 和递增版本号。编辑、删除和发送都校验 ID + 版本；同文案项不混淆，其他标签页的旧操作返回冲突。
- 交给 Pi 的项先变为 `sending`，此时禁用修改/删除/重复发送。成功移交后从可编辑队列移除；直接引导使用 Pi 原生 `steer`。已经移交或在其他终端加入的原生消息仅作只读状态展示，不能假装仍可撤回。
- `agent_settled` 通知中只安排后续事件循环投递，投递前重检运行实例、空闲、暂停、错误和审批状态。自动发送面向所属运行实例，不依赖当前前台选中的聊天。
- 发送失败保留原项、附件和错误，不自动重放结果不明的操作；用户可编辑、删除，或在任务运行时再次明确选择引导。
- 每会话最多 50 个待处理项，待发正文和图片编码总量最多 64 MB；达到上限拒绝新增并保留输入草稿/上传回执。

## 会话与生命周期

- SDK 与 TUI `/web` 都支持 Web 队列项的编辑、删除、引导。TUI 使用新鲜的会话上下文，不回调新建会话前的旧 Pi 运行时。
- 切换 SDK 聊天不停止后台任务，队列及自动投递归属原会话；刷新/断线重连从服务端恢复稳定 ID 和版本。修改不会丢失已有图片数据或附件路径。
- 暂停后可继续编辑/删除；无运行任务时不能把旧的引导点击变成意外的新任务。SDK 空闲重载保留待发队列；发送交接中拒绝重载。
- Web 新建聊天时，若 TUI 尚有待发项，会新建独立 SDK 聊天而不是替换原 TUI；用户从终端显式更换原生会话会重置该 TUI 的待发队列。
- 队列仍为进程内状态，不跨服务重启持久化；不提供重排。不绕过插件审批，不将斜杠命令伪装为排队文本。

## 契约与实现

- `SessionView.queuedPrompts`：只返回 `id/revision/text/attachments/status/error`；不向浏览器返回图片 Base64 或已隐藏的附件保存路径。保留可选原生 `promptQueue` 和 schema v1 兼容。
- `POST /api/prompt-queue`：`{ sessionId, id, revision, action }`，`action.kind` 为 `edit`（含 `text`）、`remove` 或 `steer`。校验令牌、Origin、当前会话、版本和运行/审批状态；旧状态返回 409，不自动重试。
- `editable-prompt-queue.ts` 集中处理身份、版本、交接锁、附件保留、容量与失败恢复。SDK/TUI 各自提供生命周期守卫及 Pi 投递函数。
- `PiPromptQueue.tsx` 提供真实的编辑/保存/取消、删除、引导入口；请求中禁用重复操作，保留失败编辑草稿，保存/取消后将键盘焦点还给对应行。
- 队列操作包含用户内容，已加入遥测脱敏路由。

## 验证

- 单元测试：唯一项和版本冲突、同文案项、附件/图片保留、交接锁、发送失败不重试、自动交接的暂停重检、容量和非法文本。
- HTTP 测试：鉴权、Origin、旧会话、参数、旧版本、重复操作和审批守卫。
- SDK/TUI 集成：真实模型受控流、队列编辑/删除/引导、FIFO、后台隔离、暂停/继续，以及新建 TUI 会话后的新鲜 sender。
- 浏览器：直接输入发送、入队后三个操作、取消和保存编辑、失败恢复、附件编辑、刷新、键盘展开、暂停与继续；覆盖浅色 1440px、深色 390px 和 320px 窄屏，并回归会话切换、滚动和插件同步。

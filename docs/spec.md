# pi-webapp 初版规格

## 目标

把**正在运行的同一个 Pi TUI 会话**呈现在浏览器，并提供基础控制。Pi 仍负责模型、工具、会话和持久化；pi-webapp 只提供本机桥接与 Web 界面。此项目作为独立 Pi package 开发，后续可通过 npm 发布到 pi.dev/packages。

## 本轮假设与边界

- 首个用户是本机单人用户，浏览器与 Pi 运行在同一设备。
- 用户在 TUI 执行 `/web`，按提示打开浏览器；服务只监听 `127.0.0.1`。
- 本轮控制当前会话：读取历史与流式输出、发送消息、停止当前运行、新建 Pi 会话。会话列表与切换、模型切换、压缩、树导航在后续增量中实现。
- Web 界面提供布局、侧栏、空态、图标与主题模块。Pi 适配器负责把桥接数据传入这些组件。
- Pi 新的 client/server/protocol 包仍处实验阶段，暂不作为当前 TUI 的控制通道。

## 成功标准

1. `pi -e ./pi-webapp` 加载扩展，`/web` 给出可访问的本机 URL。
2. 浏览器显示当前会话历史、运行状态与模型；TUI 产生的消息在浏览器更新。
3. 浏览器发送消息进入**当前 Pi 会话**，停止按钮取消当前运行；不会创建第二个 Pi agent。
4. 未持有随机访问令牌的请求无法读取历史或提交操作；服务退出时释放监听端口。
5. 页面在桌面与窄屏可用；空会话、断线和操作失败有明确状态。

## 架构

```text
Pi TUI + pi-webapp extension
  ├─ ExtensionAPI 观察会话事件、调用 sendUserMessage/abort
  ├─ 本机 HTTP：快照、消息发送、取消
  └─ NDJSON 流：向浏览器推送状态与消息
                   ↓
              pi-webapp Web UI
```

浏览器只依赖版本化的桥接数据结构，不直接导入 Pi 的业务类型。后续替换成 Pi 多 presentation 服务时，Web 端保持此接口。

## 项目结构

- `extension/`：Pi 扩展、HTTP 桥接、数据映射。
- `web/src/`：React 页面、Pi 适配器与 UI 组件；`web/dist/` 为 Vite 构建产物。
- `test/`：认证、路由和同会话行为的测试。
- `docs/`：规格与后续设计记录。

## 命令

- 安装开发依赖：`npm install --ignore-scripts`
- 类型检查：`npm run check`
- 定向测试：`npm run test`
- 构建网页：`npm run build`
- 本地运行：在 Pi 所在目录执行 `pi -e /absolute/path/to/pi-webapp`，然后输入 `/web`

## 代码风格与测试

TypeScript 使用严格类型与显式接口；扩展入口只组装服务，HTTP、会话投影和页面各自保持独立。测试覆盖随机令牌认证、当前会话快照以及消息操作；页面在真实浏览器检查布局、断线和键盘操作。

## 实施顺序

1. 定义桥接 DTO 和安全边界。
2. 实现当前会话快照与事件流。
3. 实现发送和停止的 Web 操作。
4. 实现布局、侧栏、空态组件与视觉资源，由 Pi 数据适配器驱动，并在浏览器核对。
5. 后续若接入富文本输入和多面板，需先建立对应的 Pi 服务适配接口。

## 待确认的后续设计

- 会话列表与切换是否需要跨多个 Pi 进程管理。
- 当浏览器与终端同时输入时，消息队列的产品规则。
- 是否提供远程访问；本机令牌机制不作为远程部署方案。

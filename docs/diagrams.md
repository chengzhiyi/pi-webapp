# Local Excalidraw diagrams

## Use

Rebuild and restart pi-webapp (`npm run build`, then restart the launcher). With `pi -e .`, rebuild, wait for all chats to be idle, then `/reload` and `/web`. A browser refresh alone does not register backend tools.

1. Open the right workbench → **Diagrams / 手绘图**. This builtin can be disabled globally in **Plugins**, like Files/Git/Terminal.
2. Ask the agent naturally, for example: “画一张分层架构图，区分入口、核心、运行库和外部服务”. No tool names or diagram IDs are required in the request. Its `diagram_create` / `diagram_patch` result displays the actual diagram inline in chat, with zoom/fit controls and **Edit**. The same draft appears in Diagrams. The plugin landing page also has a prompt field and example prompts.
3. Preview the candidate, then **Accept candidate** or **Reject candidate**. Preview is read-only. Manual editing, native undo/redo, and zoom are available after acceptance.
4. For another AI edit, use the editor's instructions field or explicitly name the diagram ID in chat. `diagram_read` obtains the latest synchronized native scene; `diagram_patch` proposes local changes, not a complete redraw. The instructions field flushes hand edits before sending the request. Ordinary chat's stop control and the editor's **Stop generation** use the existing session abort operation.
5. The editor keeps **Save / Save as** and **Export PNG** in its compact header; the current-diagram instruction field sits below the canvas and synchronizes hand edits before sending. **Files & more / 文件与更多** reveals the path, source download, transparency, revision and recovery controls. **Save / Save as** writes a workspace-relative `.excalidraw` file (default `diagrams/<id>.excalidraw`). Changing the path means Save as. A new path must not exist. An existing file can only be updated from its loaded content hash. On conflict, reopen the file or choose a new path; there is no force-overwrite button.
6. **Download source** downloads the current confirmed scene, including unsaved manual changes. **Export PNG** exports that scene, not a pending candidate, with a white or transparent background. Filenames include the draft revision.
7. Open saved files by relative path, or import a downloaded `.excalidraw` file using the file picker. Imported files are new drafts, not write access to the original host path.

No model is needed to open, manually edit, save or export a diagram. Model calls use the existing provider and its normal billing/data policy; this plugin does not make additional model calls on its own. Fixed test fixtures are not a guarantee of any model's semantic accuracy.

## Ownership and boundaries

- Implementation: `src/plugins/builtin/diagrams/{contract,server,client}`. This first version is a bundled plugin, **not** an independently published npm plugin. It uses the same registration, workbench, ownership and real enablement gates as the other builtins. External plugin static-resource contracts are unchanged.
- `diagram_reference`, `diagram_create`, `diagram_read`, `diagram_patch` are registered in the Pi extension and passed as SDK custom tools to each retained workspace runtime. Execution goes through `ServerPluginRegistry.runAgentAction`, so disabling the plugin also blocks its tools. Tool schemas may remain visible in an existing runtime, but execution fails closed.
- Candidates contain at most 30 new nodes / 60 new edges (including text and layer containers). `diagram_reference` returns local format guidance and a layered architecture example; it is not evidence of model generation quality. Nodes support `process`, `decision`, `terminal`, `text` and `group`, explicit coordinates/dimensions, hexadecimal colors, line style, font size and one-level `groupId` membership. Text nodes are standalone titles/annotations; group nodes are background containers with top-left headings. Explicit-layout diagrams should provide coordinates for every node. Edges support color, solid/dashed/dotted strokes and up to 12 absolute intermediate waypoints, while their endpoints remain bound.
- Patches add nodes/edges, change a shape's bound label, remove native IDs, or `updateElements` by ID for geometry, colors, font size or standalone text. A bound text ID must be edited via its container. Explicitly moving/resizing a shape reroutes incident arrows; this may change those arrows' manual routing. Unrelated elements/paths remain unchanged. New elements without explicit positions still use the conservative append-to-right policy. Group membership assists native multi-selection, not nested layout; changing a group container's geometry via AI does not automatically move its children. For larger reads, select `elementIds`; the default tool result is capped at 100 elements. The native scene is capped at 400 elements / 512 KiB.
- The native scene, not the initial graph, is authoritative after manual editing. Browser changes are serialized and synchronized with compare-and-swap draft revisions. Candidate acceptance checks the original revision; stale candidates can be rejected but cannot replace newer edits. Disk saving also checks the loaded SHA-256, uses an exclusive sibling lock, fsyncs a temporary file, and commits atomically. New-file creation is atomic and no-replace.
- Paths must remain within the current workspace. Absolute paths, symlinks, non-regular files and other extensions are rejected. Only the conventional `diagrams/` parent is automatically created. Locks are not automatically stolen: if a process crashes, stop all writers before inspecting/removing that specific `.excalidraw.lock`.
- Optimistic hashes and cooperative locks are not mandatory OS locks on arbitrary external editors. An uncooperative same-user process can still race the last check and replacement of an existing file. Trusted plugins run with host permissions; this is not a filesystem sandbox.
- Runtime drafts/candidates are session-owned and held by the running bridge. Browser-native draft backups protect hand edits/accepted scenes across tab close and refresh on the same origin. Diagrams lists available browser backups for recovery as new drafts, including after bridge draft IDs expire. This is best-effort, may fail under browser storage policy/quota, and is not crash-proof persistence. **Save files for durable recovery across service restarts, changed ports, or cleared browser storage.** Unaccepted structural candidates are not promised durable storage.
- Local import supports basic native rectangles, diamonds, ellipses, text, arrows, lines and free drawing. Images, embedded frames, remote links and binary files are rejected, not silently discarded. Arbitrary external scenes are not promised compatible.
- No Excalidraw server, account, cloud sharing, remote library, independent model, telemetry service or headless browser is added. PNG requires an open browser. SVG, collaborative editing, full history UI and selected-region AI editing are not implemented.

## Resource loading and maintenance

`DiagramPanel.tsx` is a thin plugin entry. `Canvas.tsx`, the official `@excalidraw/excalidraw@0.18.1` component, and its CSS are dynamically loaded only when a diagram preview or editor is visible. Hidden workbench tabs retain their small models but unmount native canvas instances. Module code remains in the browser cache; closing a tab does not unload JavaScript. Inline artifacts observe the same session/diagram model as the editor, render a font-embedded SVG into an inert blob image, and never mount another editable canvas. Offscreen previews defer editor-module loading and refresh work. Preview exports are debounced during hand edits. Merely viewing a candidate does not accept it or save a file.

`scripts/excalidraw-assets.mjs` copies the package's unmodified WOFF2 fonts, including CJK subsets, to an explicit build inventory. `readAssetManifest` serves only listed safe assets, not arbitrary nested files. `canvas-env.ts` configures same-origin fonts before editor initialization. The pinned production font loader otherwise always appends a CDN fallback; a small checked build transform removes that fallback. Upgrading the editor requires reviewing this transform (an unexpected source shape fails the build), licenses and regressions. The default CSP is not relaxed for fonts, scripts, images or remote connections.

The native editor's cloud library UI and image/embed insertions are not part of this supported surface. Drop/import validation still applies. Existing editor dependency low-severity advisories should be monitored; `nanoid` and `lodash-es` overrides pin patched compatible public APIs. Do not run an automatic major-version audit downgrade. Bundled font notices are in `assets/diagrams-NOTICES.txt`; the npm package's license label alone does not describe every font.

## Checks

```sh
npm run check
npm run build
npm test
npx playwright test test/browser/diagrams.spec.ts test/browser/diagrams-samples.spec.ts test/browser/diagrams-experience.spec.ts
git diff --check
```

Tests cover authenticated/session-scoped operations, path and symlink rejection, bounds, imports, hashes, atomic creation, concurrent writers, stale drafts/candidates, plugin disablement, a real SDK tool loop with a deterministic model fixture, and native browser editing/exports. Browser samples check ten fixed Chinese structures plus a 30-node timing fixture, bindings, labels and node overlap. They also verify artifact cards, manual-position preservation, rejection, label updates, source/PNG downloads, refresh, desktop-width and mobile-width viewports, and no third-party HTTP requests. The reference-experience tests additionally verify a layered Chinese architecture inline before any editor opens, same-model preview/editor updates, group headings and backgrounds, free text, dashed boundaries/paths, targeted style/geometry changes, inert preview zoom, compact default controls, saved source/PNG and no third-party HTTP at 1440/390 px. Chromium viewport checks are not a packaged Electron or cross-browser certification.

## Reference-experience scope

The UI follows the supplied Doubao screenshots' core pattern: a diagram embedded in the answer, an Edit entry into a large Excalidraw workbench, and composition of layers/titles/notes rather than identical node chains. This is an implementation within the existing plugin/agent infrastructure, not a claim to reuse Doubao's MCP App or its private implementation. No new MCP server is installed. Static screenshots do not establish streaming generation; this version renders completed candidates and does not simulate incremental drawing. No external “Open in Excalidraw” upload/share action is added. Ordinary chat does not silently guess a target when multiple diagrams exist: use the editor's instruction field to refer to the current diagram, or specify which diagram in chat. Existing candidate confirmation and disk conflict rules remain in force.
